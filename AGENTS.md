# Notes
- Auth uses NextAuth.js v5 credentials provider with bcrypt-ts password hashing.
- Database helpers live in `lib/db/queries.ts` using Drizzle ORM and Postgres.
- `DUMMY_PASSWORD` is generated to mitigate timing attacks when credentials fail.
- Middleware handles redirect logic between `/login`, `/register`, `/share/*`, and authenticated routes.
- When running the Next.js dev server manually for Playwright (`PLAYWRIGHT_MANUAL_SERVER=true`), export `PLAYWRIGHT=true`, `NEXT_PUBLIC_PLAYWRIGHT=true`, and `NEXT_FONT_GOOGLE_MOCKED_RESPONSES=$(pwd)/tests/mocks/google-fonts.js` so the server sticks to the in-memory database and the UI keeps using hermetic assets.
- Sidebar history now seeds its initial page on the server (`lib/history/config.ts`, `app/(chat)/layout.tsx`) and disables SWR revalidation whenever the Playwright flag is set, preventing `/api/history` fetches during offline runs.
- Playwright requires both `pnpm exec playwright install` (Chromium build 1193) and `pnpm exec playwright install-deps` to provide the GTK/video libraries in this container; run these after `pnpm install` when rebuilding the environment.
- After running `pnpm install`, rerun `pnpm exec playwright install chromium` so the cached browsers match the upgraded Playwright CLI (current build: 1193).

- Playwright-specific runs now lower the bcrypt salt rounds to four so authentication setup finishes quickly while production keeps the stronger cost factor.

- When Playwright flags are enabled, the auth/chat providers now lazy-load `@ai-sdk/openai` via `require(...)`, so the module isn’t needed during hermetic runs. Production deployments still throw a clear error if the dependency is missing.

- Playwright’s dev server output is persisted to `tests/.logs/next-dev.log` on every run via `tests/utils/run-next-dev.ts`, simplifying post-failure debugging.
